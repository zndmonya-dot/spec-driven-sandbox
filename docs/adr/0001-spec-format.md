# ADR 0001: 仕様は Gherkin と型・スキーマの二層で書く

- 状態: 採用
- 日付: 2026-10-29

## 背景

仕様駆動開発で、人と AI エージェントの両方が同じ仕様を読み、
その仕様から自動でテストが走る状態を作りたい。

## 決定

1. **振る舞い**は `specs/**/*.feature` に日本語の Gherkin で書く。
   シナリオはそのまま Vitest のテストとして実行する（QuickPickle を使う）。
2. **データの形と境界**は `src/**/schema.ts` に Zod で書く。
   TypeScript の型はスキーマから導き、二重に書かない。
3. 言葉は `CONTEXT.md` の用語だけを使う。

## 理由

- Gherkin は人が読める。シナリオがそのままテストになるので、仕様と実装がずれたらテストが落ちる。
- Zod は型検査と実行時検査を一つの定義で済ませられ、モジュール間の契約に使える。

## 捨てた選択肢

- 自然言語の受け入れ条件だけ：テストとの対応を手で保つ必要があり、ずれに気づけない。
- TLA+ などの形式仕様：この規模では学習コストに見合わない。並行処理を扱う段階で再検討する。
