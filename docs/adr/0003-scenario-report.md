# ADR 0003: 対応表は Vitest のレポーターで作り、CI の Summary に書く

- 状態: 採用
- 日付: 2026-10-29
- 注文書: #10

## 決定

1. 対応表を作る中身（合否の判定と合計）は `src/report/` に置き、仕様のテストで確かめる。
2. テスト結果を集めて Summary に書くのは `scripts/scenario-reporter.ts`（Vitest のレポーター）。`npm test` のたびに動くが、`GITHUB_STEP_SUMMARY` がない手元では何も書かない。
3. シナリオアウトラインは例の行ごとに同じ名前になるので、表では「（例 n）」を付けて見分ける。

## 理由

- CI の設定（verify.yml）を変えずに済み、テストを2回走らせることもない。
- 書き出し先を CI に限れば、手元の作業でファイルが増えない。

## 見直す条件

PR へのコメントなど、Summary 以外にも出したくなったとき。
