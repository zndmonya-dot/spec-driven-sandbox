# 注文書の書き方

このリポジトリでは、人は「何を作りたいか」を注文書に書くだけです。
作るのも、合格しているか確かめるのも AI と自動チェックがやります。

GitHub の Issues で「New issue」→「注文書」を選ぶと、下の欄が並んだ画面が開きます。

## 1. 作りたいもの・なぜ必要か

一言でかまいません。「なぜ」があると、AI が細かいところを判断しやすくなります。

## 2. 決まりごと（いちばん大事）

「こうなったら合格」を、具体的な数字を入れて書きます。形は3行です。

```gherkin
シナリオ: 在庫数を超える出庫は断られる
  前提 商品 "ABC-0001" の在庫数は 2 個である
  もし 商品 "ABC-0001" を 3 個出庫する
  ならば "在庫不足" で拒否される
```

- **前提**：最初の状態
- **もし**：すること
- **ならば**：こうなっていれば合格

書いた決まりごとは、そのまま自動テストになります。
AI はこれが全部合格するまで作業を続け、決まりごとそのものは勝手に書き換えません。

よい決まりごとのコツ：

- 「いい感じに」ではなく、数字や名前で書く（2 個、"ABC-0001"）
- 1つのシナリオに決まりごとは1つ
- うまくいく場合だけでなく、断られる場合も書く

## 3. 新しく使う言葉・やらないこと

`CONTEXT.md` にない言葉を使うなら、意味を一行で。
「今回はやらないこと」を書いておくと、AI が作りすぎるのを防げます。

## 注文のあと（自動）

1時間に1回、クラウド上の Claude が `order` ラベルの Issue を見回り、まだ手が付いていない注文書を1件ずつ処理します。
GitHub に鍵を置く必要はありません。AI から質問が来たら、Issue にコメントで返事を書いてください。次の見回りで続きから進めます。

## 注文のあと

1. AI が注文書を読み、わからないところを1つずつ質問します
2. 決まりごとを `specs/` の仕様ファイルに写し、まだ作っていないので不合格になることを確かめます
3. 作って、`npm run verify` が合格するまで直します
4. PR を出します。人は決まりごとどおりかを見てマージします
